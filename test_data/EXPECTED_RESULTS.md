# Sales vs Settlement — test data answer key

Generated by `make_test_data.py`. Every number below is what the app must show.

## How to run the test

1. **Upload data** — upload the five files in `2019-01/` with data month **Jan 2019**, then the five in `2019-02/` with data month **Feb 2019** (dataset = file name).
2. **Run reconciliation** — month **Jan 2019** (one month), platform **TESTMART**, tolerance **0.01**, return window **30**, tax tolerance **1.00**, standard column mapping. → compare with *Run 1* below.
3. Run again for **Feb 2019**, same settings. → compare with *Run 2* (needs Run 1 first: it carries Jan's open items).

> Run Jan before Feb, and only once each: open items are carried from run to run, so re-running Jan after Feb changes nothing, but a fresh database is the cleanest. Data months 2019 + platform TESTMART keep this apart from real data. Do not open the CSVs in Excel and save them (Excel drops the leading zeros of `0091001`).

> **Completely blank column**: the test rows fill every standard column, so a fresh database gives 0. If your database already has extra columns from real uploads (e.g. `Settlement_on_2024_02_02`), each of those is blank for the test rows and is reported once per run — those findings are expected and are not counted below.
